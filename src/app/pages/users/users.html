mergeMap

Runs All in Parallel

Use case: Bulk detail loading. mergeMap subscribes to all inner Observables simultaneously. It does not wait for one to finish before starting the next. Results arrive in whatever order the server responds — not the order they were requested.

mergeMap:     fetch(1) fetch(2) fetch(3)  ← all PARALLEL
                 │        │  │
             res(1)    res(3) res(2)      ← arrival order varies

Processes One at a Time, in Order

Use case: Sequential save operations. concatMap queues emissions and subscribes to the next inner Observable only after the current one completes. This guarantees ordering — User #1 is fully saved before User #2 begins.

                       waits ↑       waits ↑

Ignores New While Busy
